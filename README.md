为什么使用go-flow?
视频加工流往往包含一些列步骤，审核，分类、格式化，视频封面生成，打标签等，如果业务逻辑硬编码，后期代码难以维护
通过go-flow库实现视频加工流中的DAG，将视频加工中的步骤和步骤关系解耦，由go-flow去管理各节点，go-flow不仅支持将节点连接起来，还支持并行执行、节点间的条件分支判断和聚合等功能
在企业级系统中，这些节点会是真实的微服务接口，在我的项目中只是进行了简单的mock。


重构

引入kratos框架重构单体应用 将其微服务化拆分为内容管理，内容加工，内容网关三层
内容网关：
主要是一些中间件，比如参数校验，redis session鉴权，promethus监控中间件，
监控指标上报：
引入promhttp库自动采集路由表中的接口数据并上报到promethus，而监控的指标主要有counter指标和summary概要指标
引入zipkin相关的库搜集接口级别或者函数级别的调用链路信息，一条trace_id对应多个spanid。接口级别使用中间件实现上报，函数级别需要自定义span
内容管理：
核心业务CRUD接口实现，主要是gorm的接口
内容加工：
提供分布式的内容加工服务


依赖注入，grpc支持，注册中心支持等

一致性哈希将数据库分表
用hash/fnv函数将内容ID哈希成64位整数，64位是为了避免哈希冲突，再将hashval与子表数量取余，这样数据均匀的分布到（0，mod）区间，避免数据倾斜，
连续n次传入的内容ID计算得到的hash值都是一样的，可以稳定的定位对应的子表
